# rdpkey — проброс горячих клавиш в RDP RemoteApp

Утилита без зависимостей: пробрасывает `Win`, `Win+<клавиша>`, `Alt+Tab`,
`Alt+Shift+Tab` и `Ctrl+Esc` в полноэкранный сеанс RDP RemoteApp (RAIL).

## Зачем

В RemoteApp-режиме (окно класса `RAIL_WINDOW`) системные комбинации
перехватывает локальная Windows, и до удалённого сеанса они не доходят.
`rdpkey` перехватывает их, пока RemoteApp-окно развёрнуто на весь экран,
и доставляет в сам сеанс.

## Что пробрасывается

| Сочетание | Что делает в удалённом сеансе |
|---|---|
| `Alt+Tab` | переключение между окнами |
| `Alt+Shift+Tab` | то же самое, но перебор идёт в обратную сторону |
| `Win` | открыть «Пуск» |
| `Ctrl+Esc` | то же, что `Win` — пригодится, если клавиши `Win` нет или она не работает |
| `Win+R` | диалог «Выполнить» — запуск программы или команды по имени |
| `Win+E` | Проводник |
| `Win+D` | показать рабочий стол, свернув все окна; повторное нажатие возвращает их обратно |
| `Win+Tab` | «Представление задач»: окна и виртуальные рабочие столы |
| `Win+V` | журнал буфера обмена — вставить можно не только последнее скопированное, но и любое из предыдущих |
| `Win+<клавиша>` | прочие сочетания с `Win` работают так же; список есть в справке Microsoft |

Про `Win+Tab` стоит предупредить тех, кто виртуальными рабочими столами не
пользовался: окна с них никуда не пропадают, но с непривычки кажется, что
всё исчезло. Открытое остаётся на том рабочем столе, где его запустили, —
вернуться туда можно тем же `Win+Tab`.

Всё перечисленное перехватывается только когда в фокусе развёрнутое на весь
экран окно RemoteApp. В любой другой момент сочетания достаются локальной
машине и работают как обычно.

### Чего пока нет

`Win+Shift+S` (вырезка части экрана) доходит до сеанса как `Win+S` —
открывается поиск, а не «Ножницы». Добавочный модификатор в аккорд с `Win`
не попадает, поэтому `Shift` теряется по дороге; это касается любого
сочетания вида `Win+<модификатор>+<клавиша>`. Разбор — в `hotkeys.md`.

`Ctrl+Alt+Del` не перехватывается принципиально: эту комбинацию обрабатывают
ядро и `winlogon` до любых пользовательских хуков. Это защита ОС, и обходить
её не следует.

## Как работает

Глобальный низкоуровневый хук клавиатуры (`WH_KEYBOARD_LL`) из своего
процесса глушит комбинацию и пере-постит `WM_KEYDOWN`/`WM_KEYUP` в окно
класса `IHWindowClass` процесса `mstsc` через `PostMessageW`. Провод
строится по скан-коду: `Win` идёт со скан-кодом `0x5B`, но vk `0x41` —
обход фильтра Win-клавиши; `Tab` в `Alt+Tab` — без alt-контекста (обход
фильтра Alt+Tab в `mstscax`).

Инъекции в чужой процесс нет — `PostMessage` работает межпроцессно, а
LL-хук глобален по своей природе. Перехват только в полном экране: в
оконном режиме вложенного RDP фокусный `RAIL_WINDOW` относится не к тому
слою, и комбинации ушли бы не на целевую машину.

## Сборка

MinGW-w64 UCRT (`C:\msys64\ucrt64`). Запустить `build.cmd` →
`builds\rdpkey.exe` (самодостаточный, статически слинкованный, с иконкой
из `resources/app.ico`).

## Использование

1. Запустить `rdpkey.exe` без аргументов — покажет справку и путь к себе
   (в реестр ничего не пишет).
2. Правый клик по `.rdp` → «Открыть с помощью» → «Выбрать другое
   приложение» → указать `rdpkey.exe` (можно отметить «Всегда»).
3. Открывать `.rdp` как обычно. `rdpkey` поднимет сеанс через `mstsc` и
   будет пробрасывать горячие клавиши, пока сессия жива (свёрнутое окно —
   тоже живая сессия). Когда сессию закрывают, `rdpkey` завершается сам.
